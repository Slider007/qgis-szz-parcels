# Плагин QGIS «Участки в СЗЗ»

Устройство и правила отбора — в `README.md`. Общие правила модулей компании — в
`~/Projects/QGIS/CLAUDE.md`.

## Как выпускать версию

1. `tests/run_tests.sh` на 3.44 и 3.40 — все проверки должны пройти.
2. Поднять `version=` и дописать `changelog=` в `szz_parcels/metadata.txt`.
3. После подтверждения — коммит и пуш, затем релиз с архивом:
   `gh release create vX.Y.Z "$(./build_zip.sh)" --title X.Y.Z --notes "…"`.
4. Дальнейшие шаги — в локальном `CLAUDE.local.md`.

## Устройство

- `core.py` — общий для алгоритма и подсветки расчёт: `area_geometry` (полигоны и
  замкнутые линии → площадь), `Classifier` (меры контура: площадь, в предприятии, в СЗЗ,
  расстояние; сложение контуров; вид строки), `collect` (группировка по кадастровому
  номеру), `split` (три списка по порядку таблиц), поиск полей по названиям.
- `processing/registry_algorithm.py` — `szzparcels:registry`: два слоя, xlsx, docx.
  Заголовки слоёв (псевдонимы) — `INSIDE_ALIASES` / `near_aliases`.
- `export.py` — xlsx и docx без сторонних библиотек (Office Open XML через zipfile).
- `dialog.py` — окно: выбор слоёв, вопрос о зонах, подсветка `QgsRubberBand`.
- `plugin.py` — кнопка, окно в одном экземпляре, расчёт в фоне
  (`QgsProcessingAlgRunnerTask`), слои в группу, кнопки «Открыть Excel/Word».

## Решения пользователя

- 2026-09-29: таблицы — кадастровый номер, «ВРИ» и «ВРИ по документу». Отдельного ВРИ
  по классификатору нет ни в выгрузке НСПД, ни в КПТ «Сводный импорт» (`use_value`
  заполнен у 1 из 1817): по решению пользователя вместо «ВРИ» — категория земель.
- Частично попавший участок — в таблице 1; доля в СЗЗ — по галочке. Участки самого
  предприятия не учитываются. Результат — слои, Excel и Word (A4, оформление
  произвольное). Несколько зон в слое СЗЗ — вопрос в окне.
- 2026-09-29: пустая категория и подобное «не определена» (`UNKNOWN_CATEGORY`) —
  «Категория не установлена», как в выписке ЕГРН; прочие пустые ячейки (ВРИ по документу, номер) — «—».
  «Значение отсутствует» / «Неопределено» в ВРИ по документу остаются как есть.
- Неверная СК части объектов в файле («реальные данные будут в нужной системе») —
  модуль не проверяет и не чинит.

## Грабли

- В присланной пользователем выгрузке НСПД 580 из 881 контуров записаны в EPSG:3857 при
  заявленной МСК-23, и в них 281 участок, которого нет в МСК-части. Прогон на этих данных —
  `tests/check_real_local.py` (вне git: пути к рабочим папкам, см. `CLAUDE.local.md`); он
  переводит такие контуры в копии в памяти.
- Processing по умолчанию обрывает расчёт на неверной геометрии: в алгоритме
  `context.setInvalidGeometryCheck(NoCheck)`, контуры чинит `makeValid`.
  `Qgis.ProcessingAlgorithmFlag.SkipGeometryValidityChecks` в 3.40/3.44 нет.
- `Qgis.LayerFilter.A | B` в PyQt5 — int, а `setFilters(int)` устарел: оборачивать в
  `Qgis.LayerFilters`.
- Подсветка убирается в `hideEvent`: Esc вызывает `reject()`, минуя `closeEvent`.
- Запрос участков — только в прямоугольнике зоны поиска (`setFilterRect`): участки без
  геометрии в него не попадают и не упоминаются.
- В настоящем QGIS на карте всегда есть ~16 своих `QgsRubberBand`: проверять разницу
  до и после окна.
- `run_tests.sh <скрипт> <аргументы>` передаёт аргументы скрипту.
- Пути к рабочим данным пользователя (Яндекс.Диск, названия заказчиков) в репозиторий не
  кладутся: только в файлы `*_local.py` и `CLAUDE.local.md`.
- Значок — первый вариант (участки, красная СЗЗ, предприятие в оранжевом пунктире).
  Надпись «СЗЗ» на значке и плашку в стиле «СК проекта» пользователь пробовал и
  отверг (2026-09-29): не возвращать.
- Файлы по умолчанию — в подпапке «Карты СЗЗ» рядом с проектом (решение 2026-09-29);
  папку создаёт алгоритм при записи.
